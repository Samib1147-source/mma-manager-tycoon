# MMA Manager Tycoon — AGENTS.md

Unity 6 (6000.5.9f1) 2D project, Universal Render Pipeline 17.6.0, Input System 1.20.0.
There is **no CLI build/test command** — everything runs inside the Unity Editor. Open the folder as a Unity project.

## Code layout (all project code is here)
- `Assets/MmaManagerTycoon/Scripts/Runtime/TrainingPreview.cs` — only runtime behaviour (`MmaManagerTycoon` namespace). MonoBehaviour with an `OnGUI` HUD (fixed 1280x720 layout); input via `Keyboard.current` (1 Jab, 2 LowKick, Space train, P pause).
- `Assets/MmaManagerTycoon/Scripts/Editor/` — all editor tooling (`MmaManagerTycoon.Editor` namespace):
  - `TrainingPreviewBuilder.cs` — builds `TrainingPreview.unity`, slices idle/jab sprite sheets, creates `Idle.anim`/`Jab.anim`/`Fighter.controller`/`PixelArt.mat`, then auto-runs play-mode validation.
  - `LowKickIntegration.cs` — adds the LowKick state + transitions to `Fighter.controller`, then play-mode validation of pause/switch/strike behaviour.
  - `GymBackgroundBuilder.cs`, `GymWallInstaller.cs`, `GymWallReview.cs`, `WoodenFloorInstaller.cs`, `WoodenFloorReview.cs` — approved-asset installers and scene reviewers.
- `Assets/MmaManagerTycoon/TrainingPreview/` — **generated output** (scenes, controller, anims, material, `build-complete.json`). Regenerated by the builder scripts; treat as build output, do not hand-edit.
- `Assets/Scenes/SampleScene.unity` — the **only** scene in Build Settings. Preview scenes are opened additively by editor scripts, not via Build Settings.
- `Assets/Settings/InputSystem_Actions.inputactions` — input-actions asset referenced by EditorBuildSettings; runtime code reads `Keyboard.current` directly.

## The one thing that will surprise you
Every editor script in `Scripts/Editor/` is marked `[InitializeOnLoad]`. They run automatically after domain reload / project open: they reimport sprite sheets, generate assets, and **automatically enter Play Mode** to run validation. Expect the editor to "do things" on open — do not kill it mid-import.

- Failures are thrown as exceptions and written to `error.txt` / `build-error.txt` / `integration-error.txt` in those output dirs.
- Some builders refuse to re-run if their output marker already exists (`build-complete.json`, `unity-integration.json`, existing preview scene) — delete the marker/output to force a rebuild.

## Pixel-art import rules (enforced and asserted by the builders)
Sprite sheets under `Assets/MmaManagerTycoon/Art/`: Sprite (Multiple), Point filter, 64 PPU, no mipmaps, uncompressed, `SpriteMeshType.FullRect`, no fallback physics shape, `alphaIsTransparency`. Changing these settings will break builder assertions.
